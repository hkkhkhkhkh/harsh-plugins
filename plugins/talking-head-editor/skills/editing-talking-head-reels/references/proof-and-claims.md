# Proof and claims

A sales video is a set of claims. Each one on screen either comes from a record you can name or it doesn't go on screen.
The creator's spoken words are theirs: never silently edit them. When the records disagree with what they said, the card
shows the records and the creator gets a short flag list. They decide what to re-record or cut.

## Product facts (prices, counts, guarantees, spots, formats)
Check each against the live source on the day of the edit: the live site or checkout for price, refund and guarantee terms;
the product database for counts (lectures live, modules, members); the offer document for caps ("5 spots at a time").
A plan quoted in the script is not proof that it exists today.

## Client results
Pull from the client's own records (whatever system the coach uses: check-ins, body measurements, lab reports, chat):
- **Weights and measurements**: the dated record, first and latest. Put the date range in the source line.
- **Lab markers**: two dated reports, same markers. Show only the markers that were actually retested, with units. A lab
  "smart report" often prints the previous value beside the new one: use both, and read every row (one marker can go the
  wrong way while the creator says it improved).
- **Photos**: the client's own check-in photos, matched framing (crop round the face at the same height; same aspect), labelled
  with the date. Don't print a weight on a photo unless it is that day's record.
- **Quotes**: the client's exact words from a message, check-in or video, with who/where/when ("Client on WhatsApp, 6 Nov 2025").
  Never a paraphrase in quote marks, never a "sample" testimonial. If no client said the thing the creator claims ("helped her
  walk again"), quote the closest true line ("The pain is reducing while doing the rehab") and flag the gap.
- **Videos**: cut on the client's own words, clean the audio, match the level, add a name tag only for an identity you have
  confirmed. A website caption is not identity proof: a clip once went out tagged with the wrong client.
- When a number in the voice-over can't be found in the records (a retest that was never done, an age that differs), the card
  leaves it out and the creator gets a flag.
- **Study citations** on a card come from the paper: author, journal, year, n, the actual numbers. Re-check them before
  rendering; a citation line that runs off the plate gets a second line, not a smaller font.

## Consent and privacy
- Use a client's name, face, numbers or words only with their consent (the creator confirms it). No consent: "a client" and
  no face.
- Never show a raw lab report or screenshot: they carry names, IDs, phone numbers and other markers. Rebuild the values as a
  graphic instead.
- Client media stays in the job folder on the editing machine. It never goes into a shared repo, a plugin or a public page
  other than the finished video itself.
- Medical framing: avoid "cure", "reverse", "fixed his injury" on cards even if said aloud; show the measured change and the
  client's own words. Flag treatment claims in the voice-over for the creator.

## Data access (keep secrets out of the edit)
Read client records read-only. If storage is private, prefer a local backup copy; if a server key is needed, read it from the
app's own env file at run time and never print it, write it to the job folder, or put it in a script that gets shared.
